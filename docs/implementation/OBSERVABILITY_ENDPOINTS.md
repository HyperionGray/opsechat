# Observability Endpoints

This document describes the runtime observability endpoints added for operational checks and monitoring integrations.

## Endpoints

### `GET /health`

Liveness-style health endpoint. Returns high-level process status and basic service metadata.

Example response fields:

- `status`
- `timestamp`
- `uptime_seconds`
- `version`
- `active_rooms`
- `checks`

### `GET /ready`

Readiness endpoint intended for orchestrators and load balancers. Returns:

- `200` with `status: "ready"` when local readiness checks pass
- `503` with `status: "not_ready"` when one or more readiness checks fail

Current checks are intentionally local and lightweight:

- version information loaded from `VERSION`
- APM instance initialized
- memory metrics collection path available

### `GET /version`

Returns build/service identity information:

- `service`
- `version`
- `timestamp`

### `GET /metrics/summary`

Returns an in-memory summary generated by `monitoring.ApplicationPerformanceMonitor`, including:

- total request count
- error rate
- average response time
- selected activity counters

## Request Metric Capture

`app_factory.py` captures request start time in `before_request` and records endpoint/method/latency/status in `after_request`.
Monitoring failures are intentionally swallowed so observability does not impact request handling.

## Usage

```bash
curl http://localhost:5000/health
curl http://localhost:5000/ready
curl http://localhost:5000/version
curl http://localhost:5000/metrics/summary
```
