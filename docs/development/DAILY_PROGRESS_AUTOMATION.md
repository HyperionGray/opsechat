# Daily Progress Automation

## Overview

The `daily-continuous-progress.yml` workflow now includes an automated repository context step before it creates the daily issue.

The context is generated by:

- `scripts/generate_daily_progress_context.py`

This provides a concise, machine-generated snapshot of unfinished code markers and likely cleanup targets so each daily run starts from concrete signals instead of a generic prompt.

## What gets analyzed

The script scans source-like files (`.py`, `.js`, `.ts`, `.tsx`, `.jsx`, `.go`, `.java`, `.rs`, `.sh`, `.yml`, `.yaml`) and reports:

1. Marker counts for:
   - `TODO`
   - `FIXME`
   - `STUB`
   - `TBD`
2. Top files with the highest marker density
3. Potential cleanup candidates based on filename patterns (for example: `backup`, `deprecated`, `*_old`, `*.bak`)

To keep the signal useful for implementation work, marker scanning ignores documentation and backup trees (`docs/`, `bak/`), support/asset trees (`tests/`, `scripts/`, `static/`), and common generated directories (`node_modules/`, `build/`, `.venv/`, and similar).

## Workflow integration

In `.github/workflows/daily-continuous-progress.yml`:

1. Python is set up
2. The script writes markdown context to `/tmp/daily-progress-context.md`
3. The issue creation step reads that file and embeds it into the issue body

If context generation fails for any reason, the workflow still creates the daily issue with a fallback message.

## Local usage

Run from repository root:

```bash
python scripts/generate_daily_progress_context.py
```

Optional flags:

```bash
python scripts/generate_daily_progress_context.py --root . --max-items 10
```

## Tests

Coverage for this script is in:

- `tests/test_generate_daily_progress_context.py`

The tests verify:

- code-marker counting behavior
- documentation exclusion behavior
- cleanup candidate detection behavior
